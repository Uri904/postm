# Estructura de la base de datos

La API gestiona las tablas del catálogo musical y las tablas `usuarios` y `roles` para controlar cuentas y permisos. Cada entidad tiene clave primaria generada.

```sql
CREATE TABLE artistas (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nombre VARCHAR(120) NOT NULL,
    pais VARCHAR(80) NOT NULL,
    fecha_formacion DATE
);

CREATE TABLE albumes (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    titulo VARCHAR(150) NOT NULL,
    fecha_lanzamiento DATE,
    genero VARCHAR(80),
    artista_id BIGINT NOT NULL,
    CONSTRAINT fk_album_artista FOREIGN KEY (artista_id) REFERENCES artistas(id)
);

CREATE TABLE canciones (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    titulo VARCHAR(150) NOT NULL,
    numero_pista INTEGER NOT NULL CHECK (numero_pista > 0),
    duracion_segundos INTEGER NOT NULL CHECK (duracion_segundos > 0),
    album_id BIGINT NOT NULL,
    CONSTRAINT fk_cancion_album FOREIGN KEY (album_id) REFERENCES albumes(id),
    CONSTRAINT uk_cancion_album_pista UNIQUE (album_id, numero_pista)
);

CREATE TABLE roles (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nombre VARCHAR(20) NOT NULL UNIQUE
);

CREATE TABLE usuarios (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    username VARCHAR(40) NOT NULL UNIQUE,
    email VARCHAR(254) NOT NULL UNIQUE,
    nombre VARCHAR(100) NOT NULL,
    contrasena_hash VARCHAR(100) NOT NULL,
    rol_id BIGINT NOT NULL,
    CONSTRAINT fk_usuario_rol FOREIGN KEY (rol_id) REFERENCES roles(id)
);
```

Los roles del sistema son `USUARIO` y `ADMIN`; el catálogo está limitado a esos valores. Las contraseñas se guardan con hash BCrypt. El registro público siempre asigna `USUARIO`; la creación de administradores requiere autenticarse como administrador. `POST /api/auth/token` valida las credenciales y emite un JWT firmado con HS256, válido por una hora. Las rutas protegidas reciben el token en la cabecera `Authorization: Bearer <token>`. La clave de firma se configura en `JWT_SECRET` y debe contener al menos 32 bytes UTF-8.

## Privacidad y permisos

- `GET /api/usuarios/me` y `GET /api/usuarios/{id}` requieren un token Bearer. Un usuario normal solo puede consultar y actualizar su propia cuenta; `ADMIN` puede consultar y listar cuentas y eliminar usuarios.
- `GET/POST /api/roles` y `GET/PUT/DELETE /api/roles/{id}` requieren token `ADMIN`. No se elimina un rol mientras tenga usuarios asignados.
- Las respuestas de usuarios nunca incluyen el hash de la contraseña.
- `GET /api/privacidad/politicas-seguridad` y `GET /api/privacidad/derechos-arco` presentan información general, sin autenticación. El contacto se configura con `PRIVACY_CONTACT_EMAIL`.
- La política informativa describe las categorías de datos del modelo, las finalidades del servicio, medidas configuradas, y límites del proyecto sobre retención y transferencias. El responsable del despliegue debe revisarla y completar la información organizacional y jurisdiccional.
- El endpoint ARCO explica acceso, rectificación, cancelación y oposición, así como un canal y la información orientativa que puede requerir el responsable para verificar y atender una solicitud. No recibe, registra ni procesa solicitudes; la API tampoco define plazos legales ni garantiza su resolución. Actualizar el perfil o eliminar una cuenta no constituye por sí solo un procedimiento formal para ejercer todos esos derechos.
- No guardar secretos de firma ni credenciales de producción en Postman, archivos versionados ni código. Usa HTTPS fuera del desarrollo local.

## Relaciones y normalización

- Un artista puede tener varios álbumes; cada álbum referencia exactamente a un artista (`albumes.artista_id`).
- Un álbum puede tener varias canciones; cada canción referencia exactamente a un álbum (`canciones.album_id`).
- Los datos propios de cada entidad se almacenan una sola vez. Los nombres de artista no se duplican en álbumes, ni los títulos de álbum en canciones; la API presenta esos datos relacionados en las respuestas para facilitar su uso.
- La clave única `(album_id, numero_pista)` evita posiciones de pista duplicadas dentro del mismo álbum.
- Validaciones HTTP y restricciones relacionales impiden insertar referencias inválidas. El borrado de entidades padre con dependencias devuelve `409 Conflict`.

La aplicación crea/actualiza las tablas desde las entidades JPA (`spring.jpa.hibernate.ddl-auto=update`). El DDL anterior documenta el esquema lógico equivalente. Para crear el primer administrador, configurar `BOOTSTRAP_ADMIN_USERNAME` y `BOOTSTRAP_ADMIN_PASSWORD` (mínimo 12 caracteres) antes de iniciar la aplicación.

El archivo `src/main/resources/seed-musica.sql` crea 5,000 filas de catálogo (500 artistas, 1,000 álbumes y 3,500 canciones) y está pensado para ejecutarse una sola vez en una base vacía.
